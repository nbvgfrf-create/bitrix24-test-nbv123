# Bitrix24 XLSX Import v3

Импортирует `companies (5).xlsx` в Bitrix24 по этапам:

1. Дистрибьюторы
2. Контакты
3. Компании
4. Адреса компаний через реквизиты

## Что переносится

- Название компании
- Тип компании
- Отрасль
- Страна
- Новый ответственный: Тимофей Жмаев
- Старый ответственный из XLSX
- Связанные дистрибьюторы
- Основные контакты
- Competitor software
- License expiration date
- Address + Address type

`Category` и `Порядковый номер дистрибьютора` сохраняются в исходном XLSX, но отдельного поля для них в текущей Bitrix24-схеме нет, поэтому они не записываются в CRM.

## Bitrix24

В `config.php` используются реальные пользовательские поля, найденные в диагностике:

- `UF_CRM_COUNTRY_IMPORT`
- `UF_CRM_OLD_RESPONSIBLE`
- `UF_CRM_DISTRIBUTOR`
- `UF_CRM_COMPETITOR_SOFTWARE`
- `UF_CRM_LICENSE_EXPIRATION_DATE`

Вебхук не хранится в репозитории. На Render проект читает уже заданную переменную окружения `BITRIX_HOOK`.

## Запуск

После деплоя:

### 1. Диагностика

`/diagnostic.php`

Должен находить Тимофея Жмаева и показывать пользовательские поля, типы, отрасли, адреса и шаблоны реквизитов.

### 2. Подготовка очередей

`/xlsx_to_json.php`

Создаёт:

- `queues/distributors.json`
- `queues/contacts.json`
- `queues/companies.json`
- `runtime.json`

Для исходного проекта ожидаемая структура данных — около 35 дистрибьюторов, 1062 уникальных контактов и более 2300 компаний. Точная цифра компаний берётся непосредственно из текущего XLSX.

### 3. Импорт

`/run.php`

Открытие страницы запускает worker и затем повторяет его примерно каждые 2 минуты. Состояние сохраняется в JSON-очередях, поэтому следующий worker продолжает незавершённый этап.

### 4. Проверка

`/check.php`

Показывает состояние очередей и проверяет несколько уже созданных компаний непосредственно через Bitrix24.

## Надёжность

Используется `batch` Bitrix24 с небольшими пачками. При ошибке отдельного элемента он может быть повторён до `MAX_ATTEMPTS`. Есть lock-файл, чтобы два worker одновременно не обрабатывали одну очередь.

Импорт использует `originatorId`/`originId`, чтобы объекты, уже созданные этим импортом, можно было распознавать при восстановлении после обрыва.

## Render

Проект запускается на `php:8.3-cli`. PHP-сервер использует `router.php`, поэтому внутренние JSON/XLSX/PHP-файлы не раздаются напрямую через HTTP.
